사용자의 자세를 분석해 피드백하고, 정상 자세에서 모니터 위치와 수평을 조절하는 시스템입니다. 비전 기반 코칭으로 시작해 실제 작업 환경을 조절하는 모니터암으로 확장했습니다.

개발 배경과 목표

자세를 알려주는 것만으로는 사용자의 작업 환경이 바뀌지 않습니다. 반대로 모니터가 사용자를 무조건 따라가면 잘못된 자세까지 따라갈 수 있습니다. 자세 판단과 환경 조절을 함께 연결할 필요가 있었습니다.

사용 흐름

카메라 영상으로 정상 자세·거북목·턱 괴기·비대칭 자세를 구분합니다. 잘못된 자세에는 교정 정보를 보여주고, 정상 자세에서는 센서와 제어 조건을 확인해 모니터가 사용자의 위치를 따라 움직이도록 합니다.

  1. 01

    사용자별 보정

    정상 자세와 거리·IMU 기준값 설정

  2. 02

    AI 자세 판단

    정상·비대칭·거북목·턱 괴기 분류

  3. 03

  4. 04

    일일 리포트

    측정 기록을 자세 분포와 누적 시간으로 확인

주요 기능과 설계

실제 동작

전체 시연 영상 보기 ↗

IMPLEMENTATION

초기 · Arduino에서 명령을 장치 동작으로

Raspberry Pi의 Serial 명령을 설정 변경·알림·카메라 보정으로 분기했습니다. 자세 상태에 맞춘 LED·부저 피드백을 구성하고, MPU6050 기울기와 목표각을 비교해 카메라 서보를 제어했습니다.

IMPLEMENTATION

고도화 · Motor1·2 제어 연결과 조건 처리

Motor1·2는 공동 개발했으며, 기존 Planner·MotorService 제어 경로에 사용자 위치 입력을 연결하고 하드웨어 통합을 담당했습니다. 입력 유효성, 준비 상태, 명령 주기, 캘리브레이션 안전 범위와 Recovery 상태를 확인하고 제어 보류 사유를 기록했습니다.

IMPLEMENTATION

알림 설정을 하드웨어 실행에 연결

PyQt 알림 설정을 Hardware Process에 전달하고 다음 실행 시 복원했습니다. 새 Pose 프레임만 기존 알림 판단·부저 서비스에 전달하고, 측정 종료 시 상태와 대기 명령을 정리했습니다.

04

문제 해결 과정

PROBLEM SOLVING · ARDUINO · SERVO

01. 보정이 끝난 뒤에도 계속되는 서보 떨림

01
문제 발생
카메라 수평 보정 완료 후에도 서보의 미세한 떨림과 소음이 발생했습니다.
02
해결 과정
보정 완료 후의 신호 유지와 다음 보정의 재시작 조건을 함께 검토했습니다. 완료 시 detach()로 신호를 해제하고, 다음 보정 시작 시 attach()로 다시 연결하도록 수정했습니다.
03
구현 결과
보정 중에만 서보 제어를 활성화하도록 변경했습니다.

PROBLEM SOLVING

02. 같은 Pose 프레임의 반복 알림 판단

01
문제 발생
하드웨어 실행 루프가 자세 추론보다 빠르면 같은 프레임을 여러 번 처리할 수 있습니다.
02
해결 과정
실행 루프의 반복과 새 분석 결과의 도착을 구분했습니다. 마지막 frame_id를 기록해 새 프레임에서만 알림을 판단하고, 측정 전환 시 추적 상태와 부저 대기 명령을 정리했습니다.
03
구현 결과
같은 프레임의 중복 판단과 측정 전환 시 이전 상태의 잔류를 방지했습니다.
