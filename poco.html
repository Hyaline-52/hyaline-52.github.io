01. 프로젝트 소개 및 개인 역할

자세 피드백에서 모니터암 제어로 확장한 POCO

POCO는 카메라 기반 자세 분석을 통해 사용자에게 피드백을 제공하고, 고도화에서는 사용자 위치와 자세에 따라 모니터암을 제어하도록 확장한 온디바이스 자세 코칭 시스템입니다.

INITIAL · 초기 개발

자세 판단을 실제 장치 알림으로 연결

카메라 기반 자세·졸음 분석 결과를 PyQt 화면과 LED·부저로 전달하고, 카메라 기울기를 자동 보정하는 시스템을 개발했습니다.

개인 담당 구현

  • Raspberry Pi–Arduino Serial 통신 및 명령 처리
  • Arduino 펌웨어와 LED·부저 알림 제어
  • MPU6050 기반 카메라 수평 보정 및 서보 제어

Pose·Face 모델과 UI·리포트는 다른 팀원이 담당했으며, 데이터 라벨링·검증에도 참여했습니다.

UPGRADE · 고도화

사용자 입력을 모니터암 제어로 연결

사용자 위치·자세와 ToF·IMU 센서 입력을 활용해 모니터암의 전후 이동과 화면 수평을 제어하는 시스템으로 확장했습니다. 비정상 자세에서 무조건적인 추종을 제한하는 것을 팀의 제어 목표로 삼았습니다.

개인 담당 수정·통합

  • Hardware Process와 Motor1·2 제어 경로 연결
  • 입력 유효성·장치 준비·안전 범위 및 명령 주기 처리
  • 모터 캘리브레이션 참여 및 하드웨어 통합
  • PyQt 알림 설정·Pose 입력과 기존 부저 서비스 연동

기존 Planner·IK·MotorService 전체, Motor3·4 수평 제어, AI 모델과 UI 전체는 공동 또는 타 파트 구현과 구분합니다.

02. 초기 개발 — 하드웨어 통신 및 제어

분석 결과를 실제 하드웨어 동작으로 연결

Raspberry Pi에서 전달하는 자세 판단·설정·보정 명령을 Arduino 펌웨어에서 처리하고, LED·부저·카메라 서보 제어로 연결했습니다.

시스템 제어 흐름
팀 상위 SW · 카메라 / 자세 분석 / UIRaspberry Pi · 자세 분석 및 상위 SW
↓
Serial 통신 → Arduino · 명령 수신 및 분기 (개인 담당)
↓
LED·부저 알림 / MPU6050·서보 카메라 보정 (개인 담당)MPU6050 → Arduino 센서 입력 · 알림과 보정은 명령별 기능 분기
01.

Serial 명령 처리 및 상태 전달

Raspberry Pi에서 수신한 문자열 명령을 설정 변경, 자세별 알림, 카메라 수평 보정으로 분기하도록 Arduino 펌웨어를 구현했습니다.

알림 반복 횟수는 허용 범위로 제한하고, 장치 준비 및 명령 처리 결과를 Serial 메시지로 반환해 상위 소프트웨어와 연동했습니다.

02.

LED·부저 피드백 제어

자세·졸음 상태에 따라 LED 색상과 부저 패턴이 달라지도록 구현했습니다.

millis()를 이용해 LED와 부저의 반복 횟수 및 ON/OFF 시간을 각각 관리하고, 두 출력이 완료되면 처리 완료 상태를 반환하도록 구성했습니다.

03.

MPU6050 기반 카메라 수평 보정

MPU6050 가속도 값으로 카메라의 Roll 각도를 계산하고, 목표 수평각과의 오차에 따라 서보모터를 단계적으로 조정했습니다.

서보 각도 제한과 최대 반복 횟수를 적용해 제어 범위를 관리하고, 보정 완료·실패 상태를 상위 소프트웨어에 전달하도록 구현했습니다.

03. 고도화 — 모터 제어 및 하드웨어 통합

사용자 입력과 제어 조건을 실제 모니터암 동작으로 연결

고도화에서는 사용자 위치·자세 및 센서 입력을 기존 모터 제어 모듈과 연결하고, 하드웨어 준비 상태와 안전 조건에 따라 동작하도록 통합했습니다.

주요 제어 흐름
사용자 위치 입력 · ToF / Vision
↓
Hardware Process · 입력 및 제어 상태 전달
↓
Motor12Controller · 제어 조건 및 명령 처리 (개인 수정)입력 유효성 · 장치 준비 · 안전 범위 · 명령 주기
조건 불충족 시 일반 추종 제한
↓
기존 Planner · MotorService → Motor1·2 구동기존 목표 계산·명령 경로 → 실제 전후 이동

별도로 PyQt 설정과 Pose 분석 결과를 Hardware Process에 전달해 기존 알림·부저 서비스와 연결했습니다.

01.

Motor1·2 자동 추종 제어 연결

hardware_process.py에서 사용자 위치와 제어 활성 상태를 Motor12 context로 구성하고, Motor12Controller.update()가 이를 받아 기존 Planner·모터 명령 경로를 실행하도록 수정했습니다.

기존 제어 모듈을 재구현하지 않고, 사용자 위치 입력부터 실제 모터 명령까지 이어지는 제어 경로를 연결했습니다.

02.

제어 조건 및 캘리브레이션 연동

사용자 위치의 유효성, 장치 준비 상태, 명령 주기를 확인하고 조건이 충족되지 않으면 일반 추종 명령을 제한하도록 처리했습니다.

또한 기존 캘리브레이션 안전각과 작업 가능 Z 범위, Recovery 상태를 참조해 제어 가능 범위를 검사했습니다.

제어 결과와 보류 사유를 상태로 기록하고, 모터 제어 비활성화·종료 시 추종 관련 상태를 초기화하도록 구성했습니다.

03.

PyQt 설정·Pose 알림과 부저 통합

PyQt 설정 / Pose 추론↓Hardware Process · 설정 전달 / 새 프레임 처리↓기존 PostureAlertService / BuzzerService → 부저Pose 알림 판단: MEASURING 상태 · Motor12 추종과 별도 경로

PyQt에서 저장한 알림 설정을 실행 중인 Hardware Process에 전달하고, 다음 실행 시 저장된 설정을 복원하도록 연결했습니다.

또한 MEASURING 상태에서 새롭게 수신된 Pose 프레임만 알림 판단에 사용하도록 처리해 동일 프레임의 중복 판단을 방지했습니다.

기존 PostureAlertService의 판단 결과를 BuzzerService에 전달하고, 측정 상태 전환에 따라 알림 추적 상태와 대기 명령을 정리하도록 통합했습니다.

구현 범위

Motor1·2 제어 연결과 조건 처리, 캘리브레이션 참여, 하드웨어 코드 통합을 담당했습니다. 기존 Planner·IK·MotorService 전체 및 Motor3·4 수평 제어는 공동·타 파트 구현과 구분합니다.

04. 주요 문제 해결 및 기술적 개선

실제 하드웨어 문제 대응과 제어 조건 개선

01.

초기 개발 — 카메라 수평 보정 후 서보 떨림

문제

카메라 수평 보정이 완료된 이후에도 서보모터에서 미세한 떨림과 소음이 발생했습니다.

원인 검토 및 수정

보정 완료 후에도 서보 제어 신호가 유지되는 구조를 검토하고, 보정 성공 시 cameraServo.detach()로 신호를 해제하도록 수정했습니다.

이후 새로운 보정이 시작되면 attach()로 서보를 다시 연결해 기존 보정 기능을 유지했습니다.

확인 결과

서보 신호 해제 및 재연결 로직의 코드 반영을 확인했습니다. 떨림·소음 감소 효과에 대한 별도 정량 측정은 수행하지 않았습니다.

02.

고도화 — 자동 추종 제어 조건 보완

개선 과제

기존 Motor12Controller는 상태 갱신 중심으로 구성되어 있어 사용자 위치 입력을 실제 자동 추종 명령으로 연결하는 처리가 필요했습니다.

개선 내용

기존 Planner·모터 명령 경로를 활용하면서 입력 유효성, 장치 준비 상태, 캘리브레이션 안전 범위, Recovery 상태를 확인하도록 수정했습니다.

또한 상태 갱신과 모터 명령 주기를 분리하고, 제어 보류 사유를 기록하도록 구성했습니다.

확인 결과

자동 추종 경로와 조건 처리 로직의 코드 반영을 확인했습니다. 실제 추종 성능은 고도화 팀 시험 결과에서 별도로 구분합니다.

03.

고도화 — Pose 프레임 중복 처리 방지

개선 과제

Hardware Process가 Pose 추론 결과보다 빠르게 반복 실행되므로 동일한 프레임이 여러 차례 알림 판단에 사용될 가능성이 있었습니다.

개선 내용

마지막 처리 frame_id를 기록해 새로운 Pose 프레임에서만 알림을 판단하도록 연결했습니다.

또한 측정 시작·종료 시 알림 추적 상태를 관리하고, 종료 시 대기 중인 부저 명령을 정리하도록 했습니다.

확인 결과

프레임 중복 처리 방지 및 상태 정리 로직을 적용했습니다. 실제 중복 경고 발생 횟수나 개선 효과의 독립적인 비교 측정 결과는 확보되지 않았습니다.

05. 시험 및 검증 결과

실제 모니터암 추종과 안전 동작 검증

고도화에서는 POSE-ONLY 구성으로 Raspberry Pi와 실제 모터를 구동하며 동적 추종 및 안전 동작을 시험했습니다.

개인 구현과 팀 검증 범위

개인적으로 수정한 Motor1·2 자동 추종 제어 연결, 입력·안전 조건 처리, PyQt 설정·Pose·부저 통합은 코드와 커밋으로 확인할 수 있습니다.

위 정량 수치는 개인 단독 시험이 아닌 고도화 팀 전체 시스템의 실물 시험 결과이며, 특정 코드 변경만의 성능 개선 효과를 측정한 결과는 아닙니다.
