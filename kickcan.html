KICK-CAN

STM32 분산 임베디드 RC카

RFID로 사용자를 인증하고, 무선 Controller와 CAN 차량 네트워크를 연결해 주행·센서 감지·상태 표시를 구현한 차량 전장 모사 프로젝트입니다.

개발 배경과 목표

운전자 입력, 차량 구동, 환경 감지와 정보 표시를 서로 다른 노드로 나누어 실제 차량 전장의 역할 분담과 통신 구조를 작은 RC카에 구현하고자 했습니다.

담당 범위

Node 1에서 초음파·온도·조도 입력을 판단하고, 센서 Task와 CAN 송신 Task를 Queue로 연결했습니다. Main Node의 주행 상태를 수신해 방향에 맞는 초음파 경고를 전달했습니다.

IMPLEMENTATION

센서 입력을 상태로 변환

전후방 초음파는 Echo 완료와 거리 구간을 확인해 경고 단계를 만듭니다. 온도는 경고와 정상 복귀 임계값을 나누고, 조도는 두 입력의 변화와 지속 조건을 사용해 점등 요청을 구성했습니다.

IMPLEMENTATION

FreeRTOS Task와 QueueCAN

센서 Task 4개와 CAN 송신 Task를 분리했습니다. 목적지·명령·값을 QueueCAN으로 전달하고, 송신 Task에서 프레임 구성과 송신 요청을 수행합니다.

freertos.c · CAN 송신 ↗

IMPLEMENTATION

주행 상태 수신과 방향별 처리

Main Node의 전진·후진·정지 상태를 검증해 저장했습니다. 초음파 메시지는 등록 시점과 송신 시점에 방향을 확인하며, 온도·조도에는 이 방향 필터를 적용하지 않습니다.

03

구현 결과

Node 1의 센서 판단과 CAN 메시지 처리 흐름을 구현했습니다.

구현 항목결과
센서 상태 판단초음파 거리 경고, 온도 경고·복귀, 조도 점등 요청 구성
Task·Queue 구성센서 Task 4개와 CAN 송신 Task를 분리하고 QueueCAN으로 연결
주행 방향 연동Main Node의 주행 상태를 확인해 초음파 메시지 등록·송신 조건에 반영
초음파 입력 처리Echo 완료 확인·대기를 추가하고 미수신·범위 밖 입력을 CLEAR 처리에 연결

CAN 송신 확인 범위는 HAL 요청 등록까지이며, 미수신 시 CLEAR는 장애물 부재 판정이 아닌 입력 처리 정책입니다.

04

문제 해결 과정

PROBLEM SOLVING

장애물 감지 후 남는 경고 상태 처리

01
문제 발생
팀 통합 과정에서 장애물 감지 후 경고 상태가 남는 현상이 발생했습니다.
02
해결 과정
  1. Echo 완료 확인·대기 추가
  2. 미수신·범위 밖 입력을 기존 CLEAR 처리에 연결
  3. 송신 시 주행 방향을 다시 확인해 초음파 메시지 전송 조건 점검
03
결과
Node 1의 CLEAR 메시지 구성과 송신 경로를 수정했습니다. Node 2의 표시·경고 출력 완료는 확인 범위에 포함하지 않습니다.
배운 점

감지와 해제의 의미를 함께 정의해야 합니다.

메시지를 보내는 시점에도 조건이 유효한지 확인해야 했습니다.

회고
